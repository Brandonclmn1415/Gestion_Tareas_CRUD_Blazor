# SIG-T Deployment Instructions

## Overview
This document provides instructions for deploying the SIG-T (Sistema Integral de Gestión de Tareas) application in a production environment.

## Prerequisites
- IIS (Internet Information Services) installed and configured
- .NET 8 Runtime installed on the server
- SQL Server instance available for production use
- SSL certificate installed for HTTPS

## Database Setup

### SQL Server Connection String
The production connection string should be set in the `appsettings.Production.json` file for both the API and Worker Service:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=YOUR_SERVER;Database=SIGT_Database;User Id=YOUR_USER;Password=YOUR_PASSWORD;TrustServerCertificate=True;"
  }
}
```

### Database Creation
1. Run the SQL scripts in the `Database/Scripts` directory in the following order:
   - `01_CreateDatabase.sql` - Creates the database
   - `02_CreateTables.sql` - Creates the required tables
   - `03_CreateStored.sql` - Creates stored procedures
   - `04_CreateTrigger.sql` - Creates triggers for activity logging
   - `05_CreateViews.sql` - Creates database views
   - `06_SampleData.sql` - Inserts sample data (optional)
   - `07_ReportQueue.sql` - Adds DB queue table and stored procedures for asynchronous report requests (used by POST /api/reporte/tareas-finalizadas)

## Batería de pruebas

### Ejecutar la batería de pruebas (integración)
- Definir la variable de entorno `SIGT_TEST_CONNECTION` con la cadena de conexión a la base de datos de pruebas (LocalDB recomendado):
  `Server=(localdb)\\mssqllocaldb;Database=SIGT_Test;Trusted_Connection=True;`
- Ejecutar los scripts SQL en `Database/Scripts` en orden para preparar el esquema y los datos de prueba.
- Ejecutar las pruebas desde la raíz del repositorio:
  `dotnet test SIG_T.Tests/SIG_T.Tests.csproj`
- En CI, la job "Batería de pruebas" prepara la base y ejecuta las pruebas automáticamente.

## API Deployment

### Application Pool Configuration
1. Create a new Application Pool in IIS
2. Set the .NET CLR version to "No Managed Code"
3. Set the Identity to a service account with appropriate permissions

### IIS Binding Configuration
1. Create a new site in IIS
2. Set the Physical path to the deployment folder of the API
3. Configure binding:
   - Type: https
   - Port: 443
   - SSL Certificate: Select the installed certificate

### Authentication Configuration
If using Windows Authentication:
1. In IIS, navigate to the site
2. Double-click "Authentication"
3. Enable "Windows Authentication"
4. Disable "Anonymous Authentication"

If using another authentication method:
1. Configure the appropriate authentication module in IIS
2. Update the API code to handle the authentication

## Worker Service Deployment

### Windows Service Installation
1. Install the Worker Service as a Windows Service using the following command:
   ```
   sc create "SIG-T Worker Service" binPath= "C:\Path\To\SIG_T.Worker.exe"
   ```
2. Set the service to start automatically:
   ```
   sc config "SIG-T Worker Service" start= auto
   ```
3. Start the service:
   ```
   sc start "SIG-T Worker Service"
   ```

### Configuration
Ensure the Worker Service's `appsettings.Production.json` contains the correct production database connection string.

Worker behavior: The Worker polls the `ReportRequest` queue in the database and processes pending requests (generated by `POST /api/reporte/tareas-finalizadas`). Reports are generated server-side and the request is marked as processed once complete.

## Client Application Deployment

### Blazor WebAssembly
1. Publish the client application using:
   ```
   dotnet publish -c Release -o /path/to/publish
   ```
2. Copy the published files to the IIS site directory
3. Configure the API base URL in the `wwwroot/appsettings.json` file:
   ```json
   {
     "ApiBaseUrl": "https://your-api-domain.com/api/"
   }
   ```

## SSL Configuration

### Certificate Installation
1. Obtain an SSL certificate from a trusted certificate authority
2. Import the certificate into IIS
3. Assign the certificate to the HTTPS binding of your site

### HTTPS Enforcement
Ensure all HTTP traffic is redirected to HTTPS:
1. In IIS, install the URL Rewrite module
2. Add a redirect rule to force HTTPS

## Logging and Monitoring

### Application Logs
Configure log levels in `appsettings.Production.json`:
```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Warning",
      "Microsoft": "Warning",
      "Microsoft.Hosting.Lifetime": "Information"
    }
  }
}
```

### Windows Event Logs
The Worker Service logs to the Windows Event Log. Monitor these logs for errors:
1. Open Event Viewer
2. Navigate to Windows Logs > Application
3. Filter for events from "SIG-T Worker Service"

## Backup Strategy
1. Schedule regular backups of the SQL Server database
2. Store backups in a secure, offsite location
3. Test restore procedures regularly

## Troubleshooting

### Common Issues
- **Database Connection Errors**: Verify the connection string and network connectivity to the SQL Server
- **Authentication Errors**: Check IIS authentication settings and application pool identity
- **Worker Service Not Running**: Check the Windows Event Log for errors

### Logs Location
- API Logs: Check the IIS logs directory
- Worker Service Logs: Windows Event Log > Application
- Client Logs: Browser console (for Blazor WebAssembly)
